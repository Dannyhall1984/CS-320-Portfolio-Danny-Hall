CS-320 Software Testing, Automation, and Quality Assurance

This repository contains my Contact service files from Project One and my Summary and Reflections Report from Project Two. These projects helped me better understand how testing fits into software development and why it's important to check more than just whether a program runs.

How can I ensure that my code, program, or software is functional and secure?

I think one of the most important things is testing as I go instead of waiting until the program is finished. In this course, I used JUnit tests to check that my code followed the requirements and handled invalid information correctly. I also learned that just because a test passes doesn't mean everything is perfect. It's important to test different situations, review the code, and consider security issues like preventing invalid data from being accepted.

How do I interpret user needs and incorporate them into a program?
I start by looking at what the user needs the program to do and breaking those requirements into smaller tasks. For example, the Contact service needed to store information while following specific rules for IDs, names, phone numbers, and addresses. I used those requirements to guide both my code and my tests. I think asking questions and making sure the requirements are clear before starting can prevent a lot of problems later.

How do I approach designing software?

I prefer breaking a project into smaller pieces and working through them one at a time. I try to keep my code organized and test each part as I finish it so problems are easier to find. This course reinforced how important it is to think about what could go wrong, not just what should happen when everything works correctly. Going forward, I want to continue improving how I plan, test, and review my code before considering a project complete.
